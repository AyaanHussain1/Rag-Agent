LearnShift AI Web Feature Overview
==================================

Project Purpose
---------------
LearnShift AI is a web-based adaptive learning prototype for Java Object-Oriented Programming.
The competition demo combines a FastAPI backend, a Next.js frontend, MySQL persistence, JWT
authentication, grounded OOP retrieval, adaptive learner state updates, and educator-facing
evidence views.

The app demonstrates a complete adaptive learning loop:
- Collect learner evidence.
- Update concept mastery.
- Detect weak concepts and misconceptions.
- Select a next teaching or assessment action.
- Provide grounded explanations, hints, tutor reframes, and feedback.
- Surface evidence, alerts, and recommended interventions to educators.


Main User Roles
---------------
1. Learner
   A learner can log in, select or create a fictional learner profile, complete diagnostics,
   view mastery, study recommended concepts, ask the tutor for help, and take adaptive
   assessments.

2. Educator
   An educator can log in, view class-level mastery, inspect learner progress, review alerts,
   review AI usage logs, test Gemini configuration, see recurring misconceptions, and use
   recommended interventions.


Authentication Features
-----------------------
- Provides JWT-only authentication with no refresh tokens.
- Uses bcrypt password hashing through passlib.
- Uses python-jose for JWT signing and validation.
- Reads JWT_SECRET and JWT_EXPIRES_MINUTES from environment variables.
- Returns a single access token from login and register.
- Stores the access token in browser localStorage.
- Sends authenticated API requests with an Authorization: Bearer token header.
- Provides frontend auth helpers:
  - login()
  - register()
  - logout()
  - getCurrentUser()
  - authenticated fetch wrapper through api()
- Provides backend dependencies:
  - get_current_user
  - require_role
- Redirects unauthenticated frontend users to /login.
- Restricts educator pages to educator users.
- Redirects role mismatches to the correct role area.
- Navbar displays logged-in user name, role, and a logout button.

Diagnostic Flow Features
------------------------
- Requires authentication.
- Starts an initial diagnostic for Java OOP concepts.
- Loads six diagnostic questions covering:
  - Classes and Objects
  - Encapsulation
  - Inheritance
  - Method Overloading
  - Method Overriding
  - Polymorphism
- Shows each question with:
  - Concept ID
  - Difficulty
  - Question type
  - Prompt
  - Options when available
- Records learner answer text.
- Records confidence from 1 to 5.
- Tracks approximate time spent per question.
- Submits diagnostic answers to the backend.
- Updates learner mastery and recommended starting concept.
- Redirects the learner to the dashboard after submission.

Adaptive Learning Features
--------------------------
- Requires authentication.
- Lets the learner choose an OOP concept or use the recommendation.
- Supports teaching actions:
  - Let LearnShift choose
  - Simplified explanation
  - Analogy
  - Step-by-step explanation
  - Java code example
  - Prerequisite review
  - Advanced application
- Sends learner ID, concept ID, and optional action to the backend.
- Backend can select a teaching action from learner evidence such as:
  - Mastery
  - Confidence
  - Misconceptions
  - Hint usage
- Displays:
  - Generated lesson response
  - Concept ID
  - Teaching action
  - Matched adaptation rule ID when available
  - Reason the action was selected
  - Quick guiding question
  - Source references from academic OOP content
- Records teaching interactions and AI usage logs.


Tutor Mode Features
-------------------
- Requires authentication.
- Lets the learner type a confusion, wrong answer, or Java OOP question.
- Records learner confidence from 1 to 5.
- Sends the message to the backend tutor endpoint.
- Backend detects the relevant concept and likely misconception.
- Displays:
  - Tutor explanation or reframe
  - Detected concept
  - Detected misconception ID
  - Matched adaptation rule ID when available
  - Misconception bank item when found
  - Guiding question
  - Follow-up check
  - Profile update reason
  - Source references
- Records tutor interactions and AI usage logs.


Adaptive Assessment Features
----------------------------
- Requires authentication.
- Lets the learner request the next adaptive question.
- Can use the learner recommendation or a selected concept.
- Displays:
  - Selected question
  - Concept ID
  - Difficulty
  - Question type
  - Options when available
  - Reason the question was selected
  - Matched adaptation rule ID when available
- Allows learner answer input.
- Records confidence from 1 to 5.
- Provides up to three progressive hints per question.
- Tracks hint count and includes it when submitting an answer.
- Submits answers to the backend for grading.
- Shows feedback after submission.
- Updates learner profile and mastery after attempts.
- Includes safeguard behavior for direct answer requests during assessment.


Safeguard Demo Features
-----------------------
- Requires authentication.
- Provides a judge-visible page for safety and grounding checks.

- Links to the Responsible AI disclosure page.
- Uses the same protected API flow as the learner experience.

Responsible AI Disclosure Features
----------------------------------
- Explains model and API usage.
- Notes that Gemini can be used when GOOGLE_API_KEY is configured.
- Notes that deterministic grounded fallback responses are used when no API key is available.
- Lists frameworks and data sources:
  - FastAPI
  - SQLAlchemy
  - Alembic
  - MySQL
  - Next.js
  - TypeScript
  - Tailwind CSS
  - OOP academic CSV chunks
  - Misconception bank
  - Hint ladders
  - Demo assessment records
- States privacy and safety limits:
  - Use only fictional or anonymized learners.
  - The app is not AGI.
  - The app is not a clinically validated cognitive profiler.
  - The app does not replace teacher judgment.
- Recommends human educator review before classroom use.


Grounded RAG and Source Reference Features
------------------------------------------
- The app is connected to a FastAPI backend that retrieves from local OOP academic chunks.
- Explanations can include source metadata:
  - Source title
  - Source document when available
  - Chunk ID
  - Concept ID
  - Page or section when available
  - Similarity or confidence score when available
  - Excerpt
- If Gemini is configured, the backend can use it for embeddings and generation.
- If Gemini is not configured, the backend falls back to deterministic grounded responses.
- The tutor, learning, RAG, and safeguard flows avoid unsupported topics outside the configured OOP module.

Database and Migration Features
-------------------------------

- Supports MySQL through DATABASE_URL.
- Uses PyMySQL as the MySQL driver.
- Startup also calls Base.metadata.create_all for demo-friendly local setup.
- Core tables include:
  - users
  - learners
  - concepts
  - source_documents
  - learning_outcomes
  - content_chunks
  - questions
  - hint_ladders
  - misconceptions
  - learner_mastery
  - interactions
  - assessment_attempts
  - educator_alerts
  - ai_usage_logs
  - adaptation_rules
- The users table stores:
  - id
  - email
  - password_hash
  - name
  - role
  - learner_id
  - created_at
- Alembic migration 0002_users_auth creates the users table for JWT authentication.

Validation and Smoke Test Features
----------------------------------
- Validation script checks dataset coverage:
  - Source documents
  - Chunks
  - Questions
  - Misconceptions
  - Hint ladders
  - Learners
  - Demo interactions
  - Adaptation rules
- Validation script checks database readiness:
  - AI usage logs
  - Educator alert types
  - Concepts
  - Demo learners
  - Users table
  - Demo users linked to learner profiles
- Validation script checks auth behavior:
  - Protected learner routes return 401 unauthenticated.
  - Learner login returns a JWT.
  - /api/auth/me returns the current learner.
  - Learner token cannot access educator routes.
  - Educator token can access educator routes.
- Smoke test:
  - Seeds demo data.
  - Verifies unauthenticated learner access fails.
  - Logs in as learner.
  - Exercises learner profile, diagnostic, teaching, assessment, hints, tutor, and RAG flows.
  - Logs in as educator.
  - Verifies learner access to educator routes fails.
  - Exercises educator overview, alerts, learner detail, and AI log endpoints.


Typical Demo Flow
-----------------
1. Start the backend on http://localhost:8000.
2. Start the web app on http://localhost:3000.
3. Open the home page.
4. Go to /login.
5. Seed demo data from the learner or educator page if needed.
6. Log in as beginner@learnshift.ai with password123.
7. Review the linked demo_beginner dashboard.
8. Complete the diagnostic.
9. Start adaptive learning or adaptive assessment.
10. Ask tutor mode about a misconception.
11. Open the safeguard demo and test in-scope, out-of-scope, and direct-answer behavior.
12. Log out.
13. Log in as educator@learnshift.ai with password123.
14. Review educator analytics, alerts, learner evidence, AI logs, and Gemini key status.


Environment Variables
---------------------
- NEXT_PUBLIC_API_BASE_URL
  - Frontend API base URL.
  - Default: http://localhost:8000

- DATABASE_URL
  - Backend database connection string.
  - MySQL example: mysql+pymysql://username:password@localhost:3306/learnshift_ai

- JWT_SECRET
  - Secret used to sign JWT access tokens.

- JWT_EXPIRES_MINUTES
  - Access token lifetime in minutes.

- GOOGLE_API_KEY
  - Optional Gemini API key.
  - When missing, the backend uses deterministic grounded fallback responses.
